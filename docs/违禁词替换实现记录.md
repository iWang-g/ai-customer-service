# 违禁词替换实现记录

更新时间：2026-08-03

## 变更背景

原策略在机器人生成的 QA 或 AI 回复命中违禁词时，直接丢弃原回复并发送常规兜底话术。本阶段调整为“违禁词替换”：用户为每个违禁词配置替换词，系统在最终发送前替换文本中的全部匹配内容。

## 配置结构

机器人 `config_json` 新增：

```json
{
  "outbound_block_action": "replace",
  "outbound_block_rules": [
    {"word": "你好", "replacement": "您好", "enabled": true}
  ]
}
```

- `word` 是待处理的违禁词，最多 64 个字符。
- `replacement` 是发送前替换内容，最多 128 个字符，不能为空。
- `enabled` 可停用单条规则。
- 单个机器人最多处理 200 条规则。

旧的 `outbound_block_words` 配置继续兼容。旧规则没有替换词时仍使用 `fallback_reply_text`，不会因为升级而放行原始违禁内容。

## 回复处理链路

1. 入站敏感词拦截仍然优先于 QA 和 AI，不受本阶段影响。
2. QA 命中、文档检索生成和常规兜底文本都经过统一的出站规则处理。
3. 规则按违禁词长度从长到短匹配，并在一次替换过程中替换所有出现位置。
4. 替换是单次执行，不会再次把替换结果作为新输入循环替换。
5. 替换后如果仍命中任一违禁词，返回 `needs_human`，不创建发送任务。
6. QA 回复中的图片媒体不因文本替换而丢失，仍按“文本后发图”发送。
7. 未配置有效替换词的旧规则走原有常规兜底策略；兜底文本本身也会先尝试替换，替换后仍违规则转人工。

响应风险标记包含：

- `outbound_block_word`：命中了出站违禁词规则。
- `outbound_block_replaced`：至少有一处内容完成替换。
- `replacement_blocked`：替换后仍命中违禁词，已阻止发送。

## 管理后台交互

机器人核心配置的“违禁词与高敏词拦截策略”区域现支持：

- 输入违禁词和替换词后添加规则；替换词不能为空。
- 查看违禁词、替换词、启用状态。
- 启用/停用、编辑和删除规则。
- 保存机器人时真实写入 `config_json`，不再显示“同步至所有店铺”。
- 页面布局已将“违禁词处理策略”和“敏感词拦截策略”拆分为两个独立卡片，分别对应出站回复处理和客户入站消息拦截，避免两类策略混淆。
