# 产品文档语义检索升级实施方案

## 1. 文档信息

- 项目：`D:\project-electron\ai-customer-service`
- 文档性质：实施方案，不代表当前代码已经完成
- 编写日期：2026-08-27
- 目标模块：`services/knowledge-base`
- 影响链路：产品知识库文档导入、文档切片、文档检索、AI 回复二轮生成

本文用于把当前产品文档检索从“字面关键词召回”升级为“关键词 + 语义向量混合召回”。为了避免一次改动过大，实施按可独立验收的阶段推进，每个阶段都必须保留现有 FTS5/BM25 和关键词兜底能力。

## 2. 当前实现基线

当前知识库服务已经支持：

- 知识库 CRUD：`qa`、`product`、`tone` 三类。
- 产品文档导入：支持 TXT、Markdown、CSV、JSON、HTML、PDF、DOCX、XLSX/XLSM。
- 文档切片：按标题、段落、表格、列表和参数块生成 `document_chunks`。
- 字面检索：优先 SQLite FTS5/BM25，失败或无候选时回退关键词计数。
- AI 回复链路：`ai-reply` 调用 `/api/v1/documents/search`，拿到 `snippet` 后进入二轮生成。

当前明确缺口：

- 没有 embedding 生成逻辑。
- 没有向量存储表。
- 没有 cosine similarity 或其他相似度检索。
- QA 匹配仍是精确问题和关键词子串匹配，本方案暂不处理 QA 相似问。
- 前端管理后台没有检索测试入口和相似度阈值配置，本方案第一阶段不强制新增 UI。

## 3. 升级目标

第一目标是提升产品文档召回质量，让“同义表达、语序变化、口语化问法”也能命中相关产品资料。

示例：

| 客户问法 | 文档表达 | 当前字面检索 | 目标语义检索 |
|---|---|---|---|
| 这个能连手机吗 | 支持蓝牙连接移动设备 | 可能无命中 | 应命中 |
| 洗了会不会变形 | 不建议机洗，建议手洗晾干 | 可能无命中 | 应命中 |
| 这个键帽我的轴能用吗 | 兼容十字轴机械键盘 | 可能无命中 | 应命中 |
| 多久可以到 | 发货后以平台物流时效为准 | 可能弱命中 | 应命中 |

非目标：

- 不改机器人绑定关系。
- 不改 `ai-reply` 的二轮 prompt 主结构。
- 不引入重量级向量数据库。
- 不依赖线上服务实时访问 Hugging Face。
- 不把 embedding API key 或模型文件暴露给桌面端。

## 5. 推荐技术方案

推荐第一版使用：

```text
fastembed + BAAI/bge-small-zh-v1.5 + SQLite BLOB + FTS5/BM25 混合召回
```

选择原因：

- `bge-small-zh-v1.5` 更适合中文客服场景。
- 向量维度 512，存储和计算成本低。
- 模型体量约 0.09GB，适合当前 4C3.3G 云服务器。
- `fastembed` 基于 ONNX Runtime，避免引入 PyTorch。
- 保持 SQLite 单服务部署，不新增 Qdrant、Milvus、Elasticsearch 等服务。
- 与当前 `/documents/search` API 兼容，上层 `ai-reply` 基本不用改。

## 6. 配置设计

在 `services/knowledge-base/app/core/config.py` 增加配置项：

```text
KB_EMBEDDING_ENABLED=true
KB_EMBEDDING_MODEL=BAAI/bge-small-zh-v1.5
KB_EMBEDDING_CACHE_PATH=/data/models
KB_EMBEDDING_PROVIDER=fastembed
KB_VECTOR_SEARCH_ENABLED=true
KB_VECTOR_MIN_SCORE=0.5
KB_VECTOR_CANDIDATE_LIMIT=80
KB_HYBRID_FTS_LIMIT=80
KB_HYBRID_RRF_K=60
KB_EMBEDDING_BATCH_SIZE=16
```

默认策略：

- 本地开发默认可以开启 embedding。
- 如果模型加载失败，服务不应启动失败，而是记录 warning 并自动退回当前 FTS5/BM25。
- 生产部署时模型缓存目录挂载到 `/data/models`，避免容器重建后重复下载或丢失模型。
- 不在环境变量中保存任何模型访问 Token。第一版只使用公开开源模型。

## 7. 数据库设计

新增表：

```sql
CREATE TABLE IF NOT EXISTS document_chunk_embeddings (
    chunk_id TEXT NOT NULL REFERENCES document_chunks(id) ON DELETE CASCADE,
    model TEXT NOT NULL,
    dim INTEGER NOT NULL,
    vector BLOB NOT NULL,
    content_hash TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    PRIMARY KEY (chunk_id, model)
);

CREATE INDEX IF NOT EXISTS ix_document_chunk_embeddings_model
ON document_chunk_embeddings(model);
```

字段说明：

- `chunk_id`：对应 `document_chunks.id`。
- `model`：embedding 模型名，便于后续换模型后并存或重建。
- `dim`：向量维度，`bge-small-zh-v1.5` 为 512。
- `vector`：float32 小端序 bytes。
- `content_hash`：切片内容 hash，用于判断是否需要重算。
- `created_at` / `updated_at`：索引生成时间。

不建议第一版新增独立向量数据库。当前线上只有 40 个切片，哪怕增长到几万切片，SQLite 全量读取后 NumPy 计算余弦也足够支撑早期业务。达到十万级切片后再评估 Qdrant 或 pgvector。

## 9. 检索排序策略

第一版采用混合召回：

1. FTS5/BM25 召回最多 `KB_HYBRID_FTS_LIMIT` 个候选。
2. embedding 计算 query 向量。
3. 读取目标知识库范围内已启用、文档状态为 ready 的 chunk 向量。
4. 用 cosine similarity 取 Top `KB_VECTOR_CANDIDATE_LIMIT`。
5. 对 FTS 候选和向量候选做融合排序。
6. 复用现有 `_expanded_snippet()` 扩展相邻切片。
7. 返回 `top_k` 条结果。

融合算法建议先用 RRF：

```text
rrf_score = 1 / (rank_fts + K) + 1 / (rank_vector + K)
```

原因：

- 不需要强行把 BM25 分数和 cosine 分数映射到同一尺度。
- 对小数据集稳定。
- 实现简单，便于调试。

如果只有 FTS 候选：

- mode 返回 `fts5_bm25`。
- 保持当前行为。

如果只有向量候选：

- mode 返回 `vector`。

如果 embedding 不可用：

- mode 返回 `fts5_bm25` 或 `keyword`。
- 不影响自动回复链路。

## 10. 向量生成时机

文档导入：

- `_persist_document()` 插入 `document_chunks` 后，同步生成这些 chunks 的 embeddings。
- 当前文档规模小，同步生成可接受。
- 后续文档变大后再改后台任务。

文档重处理：

- `reprocess_document()` 删除旧切片时依靠外键级联删除旧 embedding。
- 新切片插入后重新生成 embedding。

数据库初始化：

- `init_db()` 创建 embedding 表。
- 不在 `init_db()` 中重算所有向量，避免服务启动被模型下载或推理阻塞。

补索引接口：

建议新增内部管理接口或脚本：

```text
POST /api/v1/documents/embeddings/rebuild
```

第一版也可以先做脚本：

```text
python -m app.scripts.rebuild_embeddings
```

考虑当前服务已有认证机制，若新增接口必须受 JWT 保护，并且只允许知识库拥有者或管理员触发。为了控制范围，第一阶段优先做脚本，不新增公网可调用接口。

## 15. 风险和处理

| 风险 | 处理 |
|---|---|
| Hugging Face 访问超时 | 使用 ModelScope 或本地上传模型缓存 |
| 模型首次加载慢 | 懒加载，首个语义检索请求触发加载；也可启动后预热 |
| 内存超过 1GiB | 生产 `mem_limit` 调整到 `1536m` 或 `2g` |
| embedding 失败导致自动回复中断 | embedding 异常只降级检索，不阻断接口 |
| 小数据集语义误召回 | 保留 FTS5/BM25，使用混合排序和最低相似度阈值 |
| 换模型后旧向量不可用 | embedding 表以 `(chunk_id, model)` 为主键，按模型隔离 |
| 线上重建索引影响服务 | 当前数据量小可直接执行；数据变大后改后台任务分批 |

## 17. 最小可交付定义

本次升级的最小可交付不是完整知识库平台，而是：

- 产品文档导入后能生成本地 embedding。
- 产品文档搜索能用语义召回命中同义问法。
- 现有 FTS5/BM25 不被破坏。
- embedding 不可用时服务自动降级。
- `ai-reply` 无需知道检索内部变化，仍通过现有 `/documents/search` 使用召回片段。
- 本地 Windows 验证完成后，再统一部署更新到云服务器。
