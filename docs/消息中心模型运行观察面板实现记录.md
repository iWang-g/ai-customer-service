# 消息中心模型运行观察面板实现记录

## 一、实现范围

本阶段保持消息中心最右栏原有布局，不扩展机器人配置或运维能力。右栏现在固定展示：

1. 当前展示模型；
2. 四个性能指标；
3. 切换模型；
4. 查看日志；
5. 最近 10 条真实事件；
6. business-api WebSocket 服务连接状态。

原“关闭机器人”入口已移除。右栏切换模型只改变统计视图，不修改机器人配置，也不会影响实际自动回复使用的模型。

## 二、性能指标口径

指标统计周期为“今日”，按 `Asia/Shanghai` 自然日计算。

### 2.1 运行时间

保留原指标卡片，当前显示 `-- / 暂未统计`，暂不采集。

### 2.2 请求处理

展示今日所选模型的真实调用次数。一次自动回复中的“意图识别”和“回复生成”分别算一次模型调用。QA 直接命中、敏感词拦截等没有请求大模型的处理不计数。

### 2.3 系统健康

计算公式：

```text
今日所选模型调用成功次数 / 今日所选模型总调用次数 * 100%
```

失败调用同样落库，避免成功率虚高。没有调用数据时显示 `0.0%`。

### 2.4 响应速度

展示从 business-api 开始请求 ai-reply，到生成最终模型回复内容的平均耗时。该耗时包含意图识别、文档检索和回复生成，但不包含后续 RPA 排队、切换会话和平台真实发送时间。

只有真正完成 `generation` 模型调用的自动回复才参与统计；QA 直接回复、常规兜底和无须回复等路径不参与平均值计算。

## 三、模型调用观测

ai-reply 的 DeepSeek 请求现在会采集：

- 调用阶段：`intent`、`generation`；
- provider；
- 实际模型名称；
- 状态：`success`、`failed`；
- 输入 Token；
- 输出 Token；
- 单次模型调用耗时；
- 失败原因。

DeepSeek `/chat/completions` 响应中的 `usage.prompt_tokens` 和 `usage.completion_tokens` 会随回复结果返回给 business-api。

business-api 新增 `ai_model_calls` 表持久化上述数据，并在 `automation_reply_runs.reply_generation_duration_ms` 保存完整的回复内容生成耗时。

本地 SQLite 旧数据库通过兼容迁移自动增加字段和表，无需手动删除数据库。

## 四、后端监控接口

新增以下接口：

```text
GET /api/v1/monitoring/overview?model=deepseek-chat
GET /api/v1/monitoring/logs?type=all&limit=100
GET /api/v1/monitoring/events?limit=10
```

### 4.1 Overview

返回：

- 当前展示模型；
- 可切换模型列表；
- 今日调用次数；
- 今日调用成功率；
- 今日平均回复生成耗时；
- 暂未实现的运行时间。

默认模型优先使用用户在 API 配置中保存的模型。可切换列表同时汇总：

- API 配置模型；
- 机器人配置中出现过的模型；
- 已产生调用记录的模型。

### 4.2 Logs

日志暂时保持简化，只展示：

- 回复日志；
- Token 调用。

回复日志来自 `automation_reply_runs`、会话、机器人、回复消息和 RPA 发送任务，展示处理方式、回复摘要、发送状态和失败原因。

Token 调用来自 `ai_model_calls`，展示模型、调用阶段、输入/输出 Token、耗时和调用状态。

### 4.3 Events

最近事件聚合以下真实数据：

- 客户消息入站；
- QA 匹配；
- 文档检索及 AI 回复完成；
- 自动回复生成；
- 无须回复或待人工；
- 自动回复提交发送；
- 平台发送成功或失败；
- 超时安抚话术提交或发送。

后端将底层状态转换为用户容易理解的中文事件文案，按时间倒序返回最近 10 条。

## 五、桌面端交互

- 顶部展示当前统计模型，并明确提示“仅切换统计视图，不修改实际配置”；
- 模型菜单只刷新当前模型的指标；
- 四个指标卡片沿用原布局；
- 日志弹窗保留“全部、回复日志、Token 调用”和关键词搜索；
- 最新事件区域固定展示最近 10 条并支持内部滚动；
- 首次进入消息中心通过 REST 加载数据；
- 收到 RPA、会话更新或自动回复完成的 WebSocket 事件后自动刷新监控数据；
- 底部服务连接状态继续表示桌面端与 business-api WebSocket 的连接情况。
