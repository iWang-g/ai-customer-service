## 2. 本阶段结果

本阶段已经打通以下流程：

```text
启动应用
  -> 注册或登录
  -> 获取当前用户
  -> 获取用户自己的会话列表
  -> 获取选中会话的历史消息
  -> 发送消息并写入数据库
  -> 创建 RPA 发送任务
  -> 通过 WebSocket 接收实时事件
  -> 退出后重新登录并恢复服务端数据
```

桌面端不再使用硬编码账号验证，也不再使用 `MOCK_CONVERSATIONS` 作为消息中心的数据来源。开发环境默认使用 SQLite，业务数据保存在：

```text
services/business-api/data/business-api.db
```

5. 平台、待处理状态和门店筛选继续在桌面端执行。

## 4. 业务服务端实现

### 4.1 用户注册

新增接口：

```http
POST /api/v1/auth/register
```

请求示例：

```json
{
  "username": "agent_01",
  "display_name": "售前客服小王",
  "password": "Example123!"
}
```

实现规则：

- 用户名统一去除首尾空格并转为小写
- 用户名不区分大小写检查重复
- 重复用户名返回 `409 Conflict`
- 密码使用 PBKDF2-HMAC-SHA256 加盐哈希
- 新注册用户角色固定为 `agent`
- 注册成功后直接返回 access token、refresh token 和用户信息
- 注册不会授予管理员权限

相关代码：

```text
services/business-api/app/schemas/auth.py
services/business-api/app/services/auth_service.py
services/business-api/app/api/routes/auth.py
```

### 4.2 开发示例数据

开发环境默认执行：

```text
services/business-api/app/services/demo_data.py
```

管理员首次创建或新用户注册时，如果该用户没有会话，会初始化：

- 1 个千牛示例会话
- 1 个抖音示例会话
- 对应的客户与客服消息
- 示例门店、未读数和会话状态

示例数据仅用于联调。通过以下配置关闭：

```env
SEED_DEMO_DATA=false
```

生产环境设置 `ENVIRONMENT=production` 后不会自动创建示例会话。

### 4.3 会话与消息权限

所有会话、消息查询和发送操作都使用 access token 中的用户 ID，并校验数据归属。

当前隔离行为：

- 用户只能查询自己的会话
- 用户只能查询自己会话中的消息
- 用户只能向自己的会话发送消息
- 访问其他用户的会话统一返回 `404`，避免暴露资源是否存在

### 4.4 WebSocket 用户隔离

实时连接管理已经从全局连接集合改为：

```text
user_id -> WebSocket connections
```

服务端只向事件所属用户广播，不会把某个用户的消息、RPA 事件或任务状态推送给其他在线用户。

WebSocket 建立时会校验：

- token 签名
- token 类型必须为 `access`
- token 必须包含用户 ID
- 用户必须存在且处于启用状态

相关代码：

```text
services/business-api/app/services/realtime.py
services/business-api/app/api/routes/ws.py
services/business-api/app/api/routes/messages.py
services/business-api/app/api/routes/rpa.py
```
