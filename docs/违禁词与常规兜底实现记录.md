# 违禁词与常规兜底实现记录

更新时间：2026-08-03

## 实现范围

本阶段实现机器人级违禁词拦截和常规兜底，不包含超时安抚调度和平台 RPA 转人工。

配置跟随机器人已经关联的平台与店铺生效，继续保存在机器人 `config_json`：

```json
{
  "outbound_block_words": ["绝对", "第一"],
  "outbound_block_action": "fallback",
  "fallback_reply_text": "您的问题我将为您接入专业产品客服，请稍后",
  "fallback_mark_human_required": false
}
```

## 回复优先级

1. 敏感词拦截（上一阶段）：客户消息命中后直接待人工。
2. QA 精确问题或关键词匹配：使用 QA 答案，仍需经过违禁词检查。
3. 意图识别和产品文档检索：有有效文档召回时调用 AI 生成回复。
4. 产品文档检索没有有效召回时：直接使用 `fallback_reply_text`，跳过回复生成模型。
5. AI 生成回复完成后：检查 `outbound_block_words`，命中则不发送原文，改用常规兜底话术。

如果兜底话术自身也命中违禁词，系统不会发送任何文本，返回 `needs_human`，避免在拦截和兜底之间循环。

首期违禁词采用不区分英文大小写的包含匹配，单机器人最多 200 个词，单词最多 64 个字符。

## 管理后台

违禁词规则支持添加、编辑、删除和真实保存；“同步至所有店铺”已移除。常规兜底话术支持编辑和保存；开启“发出兜底话术后标记待人工处理，并停止机器人处理该会话”后，兜底发送任务成功入队即复用消息中心的待人工标记。平台 RPA 转移会话属于转分流策略，尚未实现。

## 后续调整：违禁词替换

2026-08-03 起，出站违禁词处理新增独立的 `outbound_block_rules` 规则。每条规则由用户配置“违禁词”和“替换词”，QA、AI 以及兜底文本在发送前统一替换；详情见《违禁词替换实现记录》。

旧的 `outbound_block_words` 仍作为兼容配置：没有对应替换词时继续沿用本记录中的常规兜底逻辑。
