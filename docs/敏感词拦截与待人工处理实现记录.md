# 敏感词拦截与待人工处理实现记录

更新时间：2026-08-03

## 实现范围

本阶段首先实现机器人级“敏感词拦截”和会话“待人工处理”闭环，后续常规兜底也已复用同一套待人工状态。平台 RPA 转移会话仍不属于该能力。

## 策略与优先级

敏感词配置保存在机器人 `config_json.inbound_sensitive_words` 中，并跟随机器人已经关联的平台与店铺生效，不再提供“同步至所有店铺”。

客户新消息进入自动回复链路后：

1. 如果会话已经标记为待人工处理，直接跳过后续处理。
2. 否则检查当前机器人配置的敏感词。
3. 命中后标记会话待人工处理，不执行 QA 匹配、不检索文档、不调用 AI、不创建发送任务。
4. 未命中时继续原有 QA、意图识别、文档检索和回复流程。

匹配方式首期采用不区分英文大小写的包含匹配。单个机器人最多读取 200 个敏感词，单词长度最多 64 个字符。

## 会话状态

会话表新增独立字段：

- `human_required`
- `human_required_reason`
- `human_required_word`
- `human_required_at`

该状态没有复用原有 `status=pending`，避免把普通待处理状态和必须人工介入混为一谈。敏感词命中时，原因记录为 `sensitive_word`；常规兜底后标记时，原因记录为 `fallback_reply`。

机器人可配置 `fallback_mark_human_required=true`。当常规兜底话术的 RPA 发送任务成功入队后，系统立即将会话标记为待人工处理并停止机器人继续处理该会话。测试回复、建议模式或发送任务创建失败不会改变真实会话状态。

旧配置 `fallback_transfer_to_human=true` 继续兼容，但新配置字段优先。该能力仅在消息中心标记会话，不会调用原平台“转移会话”；后者属于转分流策略。

消息中心会话项会显示“待人工处理”标记；待处理筛选同时包含原有 `pending` 会话和待人工会话。对标记会话点击右键，可选择“清除‘待人工处理’标记”。

清除后机器人只处理之后到达的新客户消息，不会重放此前已被拦截的消息。如果新消息再次命中敏感词，会话会再次被标记。

## 配置示例

```json
{
  "inbound_sensitive_words": ["投诉", "差评"],
  "sensitive_word_action": "mark_human",
  "fallback_mark_human_required": true
}
```
