# 超时安抚实现记录

更新时间：2026-08-03

## 实现行为

机器人收到客户消息并允许自动回复时，会根据机器人配置启动独立的延迟检查任务：

1. 等待配置的响应时间（首期 1～60 秒，默认 10 秒）。
2. 如果正式自动回复对应的 RPA 发送任务已经完成，不发送安抚消息。
3. 如果正式回复仍未完成，则创建一条独立的 `automation_timeout` 消息和发送任务。
4. 安抚消息只创建一次，使用幂等键 `auto-timeout:{robot_id}:{source_message_id}`。
5. 安抚消息发送后不取消正式自动回复，正式回复继续执行。

敏感词命中、会话已处于待人工处理、正式结果为 `no_reply` 或 `needs_human` 时，不发送超时安抚。

## 配置字段

机器人 `config_json`：

```json
{
  "timeout_enabled": true,
  "timeout_seconds": 10,
  "timeout_reply_text": "专项客服正在赶来的路上请稍等~~"
}
```

管理后台“机器人核心配置 → 知识库与策略 → 兜底策略 → 超时安抚话术”已经支持开关、秒数和话术真实读写。

## 任务与消息

超时安抚沿用已有 RPA 发送任务通道，但消息 `source` 记录为 `automation_timeout`，方便后续统计和区分正式回复。RPA 客户端无需新增任务类型，仍按 `send_message` 处理。

## 当前边界

- 安抚任务由 business-api 进程内异步调度；服务重启会丢失尚未触发的内存计时器，后续可改为持久化调度器扫描任务。
- 安抚消息不会触发平台转人工；平台 RPA 转移能力仍属于后续阶段。
